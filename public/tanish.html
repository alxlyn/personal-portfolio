Case Study · Jan – Jul 2026

Tanish — a dating app for Central Asia

Co-founded, built the whole product, and shipped it through Apple review to TestFlight. The code is private; this is the engineering story. Walkthrough available on request.

2,200+ backend tests Cleared App Review 6 languages Co-founder

01Context

Dating apps built for Western markets translate poorly to Central Asia — literally (none of the majors ship Kyrgyz) and culturally (family reputation and safety concerns make women cautious about being visible on a swipe app). Tanish is a Kyrgyzstan-first dating app built around a staged “journey”: matches progress through challenges and conversation stages toward a real date, instead of an endless swipe feed.

I co-founded it and built the product end to end: the backend, the iOS app, the infrastructure, and the release pipeline — coordinating two contracted engineers on the early mobile core and reviewing every line that merged.

02Architecture

API — FastAPI, async SQLAlchemy 2.0, Pydantic v2; web + background worker
Data — PostgreSQL, Alembic migrations gated before deploy; Redis for rate limiting & caching
Realtime — WebSocket chat with push-notification fallback
Mobile — React Native (Expo) iOS app, EAS builds to TestFlight
Media — S3-compatible object storage, presigned upload/download, moderation pipeline
Trust — AWS Rekognition face liveness, LLM content moderation, JWT auth

Everything below is a real problem from this codebase and the decision that resolved it.

03Verifying humans without punishing users

Fake profiles kill trust faster than anything else in dating. I shipped face-liveness verification with AWS Rekognition: the app opens a liveness session, the user scans their face, the backend fetches results with short-lived STS credentials scoped per session — no long-lived AWS keys near the client.

  • Decision: an estimated-age mismatch flags the account for review instead of hard-blocking — age estimation is too noisy to auto-punish real users.
  • Decision: the liveness photo is soft-matched against profile photos; a mismatch lowers trust score rather than rejecting, for the same reason.

04The upload bug that broke a TestFlight build

Build 3 shipped with a “picture upload error” for every user. Root cause: our storage provider’s S3-compatible layer silently rejected presigned POST uploads carrying tagging metadata — it only honors presigned PUT signed over bucket and key alone.

  • Switched all media uploads to presigned PUT, signing only what the provider verifies.
  • Tagging was how we tracked unconfirmed uploads, so I replaced it with a janitor job that cross-references storage against the database and deletes orphans.
  • Verified the fix end-to-end against production storage before the next build: ticket → PUT → register → signed GET → delete.

Lesson: “S3-compatible” is a spectrum. Integration tests against the real provider catch what mocked S3 never will.

05LLM features that fail open

Matches answer challenge questions; an LLM scores the answers and shifts the pair’s compatibility score. When our OpenAI account hit a quota wall in production, nothing broke: scoring silently fell back to the baseline compatibility value, voice moderation queued, and users never saw an error.

That was designed, not lucky: every LLM call sits behind a fail-open wrapper — an AI outage degrades the experience, it must never take down a core flow. The incident cost us a feature for a day, not the product.

06Auth, rewritten by the market

We launched with phone + SMS OTP — the obvious choice until SMS deliverability and per-message cost in Kyrgyzstan said otherwise. I migrated the entire auth stack to email OTP (Twilio Verify’s email channel + SendGrid), killing passwords entirely.

  • Disposable-email domains blocked at signup.
  • Bans survive account deletion via an HMAC-hashed banned-email ledger — we can keep a bad actor out without storing their raw email after they’re gone.
  • The swap was a clean cutover: one PR, 1,500+ tests green, security-reviewed.

07Six languages, one human translator

The app ships in English, Russian, Kyrgyz, Kazakh, Uzbek, and Tajik. Kyrgyz came from a human translator’s document — I value-matched 500+ translated strings onto the existing Russian catalog programmatically, tracked the 131 gaps that fall back to Russian in a checked-in file, and kept interpolation tokens intact so nothing crashes at render.

08Discipline

  • 2,200+ backend and 800+ frontend tests; CI runs both on every PR.
  • Migrations run in a gated release step before new code serves traffic.
  • Every substantial change went through security review before merge; auth changes always.

09Status

Tanish cleared Apple’s review and runs on TestFlight with production infrastructure live. I paused it in July 2026 to focus on Mendy — the next thing I couldn’t stop thinking about.
